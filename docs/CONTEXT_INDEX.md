# Context Index — Where an agent should read first

> Context routing only. Current implementation/commit facts: FEATURE_LEDGER and PROJECT_STATUS. Current priorities: NEXT_ACTIONS.

## Session and task reading route

1. Read AGENTS.md, RULES.md, docs/NEXT_ACTIONS.md and docs/technical/AGENT_EXECUTION_CONTRACT.md; inspect current Git state and existing owner scope.
2. Read the active task entry in docs/implementation/FEATURE_LEDGER.md and docs/PROJECT_STATUS.md when current implementation evidence matters. Use docs/MASTER_PROJECT_PLAN.md and docs/ROADMAP.md for milestone questions.
3. Load applicable docs/DECISIONS.md entries, TD ownership/approval/gate sections and domain specs using the routing table below. Load docs/pipelines/ARGON_NATIVE_ASSET_PROFILE.md only for art/capability work. A docs/tooling review does not need all gameplay/art specs reread.
4. Select only relevant skills using docs/technical/AGENT_SKILL_ROUTER.md. Preserve already-read unchanged context across turns. docs/CONTEXT_AUDIT.md and old WORKSPACE_HANDOFF/IMPLEMENTATION_STATUS details are historical evidence, not current task instructions.

**Conflict policy**: Safety/canon boundaries remain highest (`AGENTS.md` Section 1). Owner-approved gameplay decisions in `docs/DECISIONS.md` and technical scope approvals in `docs/technical/TD_FREEZE_APPROVALS.md` override historical gameplay/bootstrap instructions and conflicting third-party skill defaults where explicitly inconsistent. `packages/game-data/src/index.ts` is current implementation data, not automatic approval of outdated mechanics. Never erase canonical IDs or make undocumented lore changes.

## Safe session handoff (`DOC SYNC` & `REMOTE CLOSEOUT`)

Follow `docs/technical/AGENT_EXECUTION_CONTRACT.md` Section 3 for in-task DOC SYNC and commit-policy closeout. Routine work does not require an independent ChatGPT approval or ZIP:
- When documentation updates are authorized in a task's **Documentation Allowlist**, record grounded task evidence in `docs/implementation/FEATURE_LEDGER.md` and update `docs/PROJECT_STATUS.md`, `docs/NEXT_ACTIONS.md`, `docs/ROADMAP.md`, or `docs/CONTEXT_INDEX.md` strictly according to their change triggers (recording `VERIFIED_READY_FOR_COMMIT` and `SELF_COMMIT` for the commit in flight, and exact immutable SHAs for prior commits).
- When documentation must change but the active task's **Documentation Allowlist** is `NONE`, explicitly report `DOC_SYNC_DEFERRED` with exact paths, reasons, and next checkpoint.
- In `docs/DECISIONS.md` and `docs/technical/TD_FREEZE_APPROVALS.md`, never silently convert `DESIGN_BASELINE`, `PROPOSED`, or `UNRESOLVED` into `APPROVED`, and never promote `TECHNICALLY_VERIFIED` art to `HUMAN_APPROVED`. Update docs without rewriting historical audit proof.
